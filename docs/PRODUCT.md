# 产品定义

## 定位

Intervals 是一套以中文为主、面向 Windows 与 Android 的响应式 PWA，用五线谱、音名拼写、钢琴和古典吉他声音训练音程、和弦与调内关系。当前仍处于个人使用和持续完善的 `0.x.x` 阶段，但工程与交互应按可长期扩展的中大型、半商业移动应用标准维护。

完整的当前功能清单只维护在 [`../README.md`](../README.md)；已发布版本变化只维护在 [`../CHANGELOG.md`](../CHANGELOG.md)。

## 目标用户与核心价值

- 面向正在建立音名、音级、和弦成员、转位、Voicing 与声音联系的音乐学习者。
- 让用户在“看到谱面、听到声音、作出答案、获得解释、再次试听”之间建立一致映射，而不是只记选择题答案。
- 同时支持手机触控和电脑键盘，安装后可离线练习，设置、成绩和错题在本地持续保存。
- 手机上应把系统返回操作映射到应用内上一层界面；正在答题时不响应系统返回，必须由用户明确点击“× 结束”，避免手势误触丢失本轮进度。
- 专业内容可以逐步加深，但第一次进入某个模块时必须先说明要做什么、怎样回答，再使用 Closed、Spread、Shell、Drop 2 等术语。

## 扩展判断标准

未来功能首先要回答：它是否让用户把理论或常见音乐现象与实际听觉连接起来，并能识别、说出自己听到了什么。仅仅增加一个已有成熟产品能够完成的播放器、伴奏器或内容库，不足以成为本项目的开发理由；必须有明确的训练闭环和差异价值。

候选方向可以帮助发现未来边界，但不能据此提前建设空接口或大规模框架。进入实现前应就训练目标、用户动作、反馈方式、内容与版权边界提出少量关键问题，再决定最小实现。

## 核心学习循环

1. 选择音程、和弦或调模块及练习范围。
2. 看到或听到题目，通过固定选项、音名键盘或和弦成员键盘作答。
3. 获得克制但清楚的对错反馈，以及与本题实际性质、转位和拼写一致的解释。
4. 重播题目、试听答案或谱面中的单音，再进入下一题。
5. 完成一轮练习后查看结果，并可按分类复习错题。

## 产品原则

### 音乐事实一致

显示名称、调号与临时升降号、内部乐理类型、生成的音符、谱面位置和实际播放音高必须互相一致。不能用“听起来差不多”的 MIDI 音高替代正确拼写，也不能只因界面文字正确就判定功能完成。

### 音乐学习者的实际读法优先

正式谱面遵守五线谱记法，非谱面音名、和弦标记、成员关系和讲解则应采用音乐学习者在教材、和弦谱和手写笔记中能一眼读懂的常见表达。排版不能机械地把所有升降号都当作普通正文或统一上标；应按语境保持自然重心、专业字形和清楚间距。成员关系使用 `M3`、`♭3`、`♭5` 等惯用标记，短横线保留克制留白。

### 学习解释来自真实题目

反馈中的转位、成员顺序、唱名、音程关系和音名应由当前题目的质量与排列推导，禁止硬编码某个 C 大调示例或复制一套容易漂移的说明。

### 谱面可以直接听

练习中出现的每个实际音符都应能在五线谱上直接点按试听，并播放该谱头对应的真实音高与当前所选音色。谱面不是只读插图，而是视觉、音名与听觉之间的直接入口。

### 共享结构优先

同一类规则在不同练习中应有相同表现。产品不接受不断叠加的一次性页面补丁；具体工程落点见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 和 [`DECISIONS.md`](DECISIONS.md#d-001-共享规则优先于页面补丁)。

### 层级浅、下一步清楚

导航和设置不应为了分类完整而不断加深。并列练习尽量在同一层展示；每个页面都应让首次用户知道当前在练什么、如何回答、怎样退出或继续。

### 反馈克制但可感知

对错反馈、动画和声音要能被感知，但不能过分突出或打断练习节奏。可访问性、焦点位置、键盘逻辑和触控命中优先于装饰效果。

答案解释先给音乐学习者真正需要的判断依据。显而易见的题面复述不重复堆砌；多项理由分行呈现，并用层级、对齐和局部强调建立视觉引导。

### 沉浸由结构与音乐文化建立

界面质感首先来自留白、构图、信息密度与清楚的学习层级，而不是装饰堆叠。首页可以借爵士唱片封套的近景裁切、编号、印刷色和模块节奏建立音乐语境；进入练习后应主动收敛，让谱面、声音、题目与当前动作成为视觉中心。

首页采用照片优先的编辑式配色：清透的亮蓝、朱红与荧光黄绿从同一张主图取色，可以作为完整色面，而不是被稀释成互不相关的浅色卡。大字标、照片和功能入口必须共享同一套色彩关系；主文案与统计可以进入照片扩出的负空间，避免另贴一块说明栏。主图承担丰富材质与第一视觉冲击，下方入口应主动降密度：每张照片以干净色面和真实留白为主，只保留少量、含义明确的对象，不能把四个入口做成四张同样繁复的海报。桌面以稳定的双列目录向下扩展，手机改为节制高度的单列图片流；模块增加时延续同一节奏，不为当前四项硬编码一次性布局。超宽桌面只增加外部留白，不让首页画布、主图和文字随视口无限放大；首页标题与入口标题应和二级页面保持连续的阅读尺度，避免页面切换时产生明显字号断层。字标、中文标题和数字使用高反差衬线字体建立编辑感，小标题、正文和交互标签使用轻字重无衬线字体维持清楚层级；不能回到粗体组件库式排版。照片可保留克制的胶片颗粒与真实材质，入口意象必须一眼可理解为对应的音乐关系，不能为了“艺术感”牺牲含义。音乐文化应进入信息结构和视觉节奏，不能用萨克斯、黑胶、霓虹等直白符号替代设计意义，也不能照搬任何品牌网站的具体版式。

移动端品牌识别应连续而克制：首页大字与顶栏品牌属于同一个视觉身份，收起时保持单一字标连续运动，不用两份近似文字硬切；进入二级及更深页面后，顶栏持续提供完整品牌组合。页面保持正常手指滚动，但不显示破坏构图的常驻滚动条。

### 连续练习避免机械重复

相邻题目（包括跨练习轮次边界）不应完全相同；这不等于强制整轮所有题目唯一。覆盖要求与随机感需要同时保留。

### 离线可靠、更新诚实

安装后的 PWA 应能离线完成核心练习。在线恢复时可以检查更新，但不能把“未来某次在线打开会更新”描述成离线客户端已经立即获得新版本。

## 明确避免

- 为单个练习复制乐理、记谱、键盘、焦点或播放逻辑。
- 只修界面文字而不追踪生成结果和实际声音。
- 为了未来可能需要而提前增加配置、抽象或复杂层级。
- 在未给使用方法前堆叠专业术语。
- 用强烈动画、音效或大面积视觉效果抢走练习内容的注意力。
- 把首页拆成彼此独立的文案板和海报板，或使用没有从主图取色、彼此缺乏关系的高饱和模块墙。
- 让主图和每个入口都使用相同的高密度物体、强裁切和复杂阴影，导致桌面拥挤、手机连续滚动像一整面广告色墙。
- 用通用玻璃拟态、无意义奢华留白或装饰性颗粒制造与学习目标脱节的“高级感”。
- 把标准乐理入口替换成含义不清、质感像塑料或亚克力玩具的生成式装饰图标。
- 在顶部导航和主要交互中混用粗黑底板、Emoji 音符、药丸按钮与过重状态字，破坏编辑式字体和细线图标体系。
- 让浏览器标签或 PWA 安装图标退回五线谱加彩色音符的通用音乐 App 符号；小尺寸只使用与首页一致的音程关系线标，不压缩完整字标。
- 让胶片噪点、印刷纹理或解构图形覆盖谱面、答案和触控区域，或在同一视觉方向里混用克制编辑感与高张力比波普解构。
- 把 AI 自己推测的功能当成用户已经批准的需求。
- 破坏旧设置、统计、错题或离线资源后只依赖用户自行发现。
